05

Control and intelligence

Software architecture

TARS-AI supplies the character. ROS 2 supplies the robot. A dedicated MCU supplies deterministic motion and safety.

The community software is a strong starting point for personality, speech, memory, vision and interface work. Its hobby-servo motion layer will be replaced by a supervised ROS 2 and CAN architecture designed for a one-metre walking machine.

Communication model

  • TopicsJoint state, IMU, temperatures, battery, faults and diagnostics.
  • ServicesShort operations such as reset fault, get configuration or enter maintenance mode.
  • ActionsCancellable walking, turning, gestures, homing and recovery sequences with feedback.
  • HardwiredE-stop, contactor and final power removal remain independent of ROS and the LLM.

Development sequence

  1. 01
    Digital robot

    Create URDF/Xacro from the Fusion joint layout and run every joint with mock hardware.

  2. 02
    One-joint bench

    Implement the MCU/CAN protocol, encoder feedback, limits and watchdog on one restrained actuator.

  3. 03
    Safety supervisor

    Add E-stop state, contactor control, faults, timeouts and deterministic safe stopping.

  4. 04
    Restrained motion

    Run neutral poses and gestures with the robot supported by an independent fall-arrest fixture.

  5. 05
    Walking primitives

    Develop monitored step, turn, stop and recovery actions before voice control is enabled.

  6. 06
    TARS integration

    Connect personality, speech, memory and vision through the restricted behaviour bridge.

  7. 07
    Local LLM

    Run a CUDA-backed model server on the external NVIDIA GPU and profile heat, power and latency.

Safety gate: voice or LLM-triggered motion stays disabled until physical E-stop, contactor removal, watchdog behaviour, joint limits and restrained trajectory tests have all passed.

07

Release gates

Open engineering decisions

  1. Freeze motion architecture.Define walking degrees of freedom, hard stops and complete collision sweeps.
  2. Calculate loads.Resolve holding, landing, recovery, fault and fatigue cases before choosing actuators.
  3. Select the LLM GPU.Choose exact card, VRAM, dock, PSU and cooling so the bay can be finalised.
  4. Close the mass budget.Reconcile aluminium body mass, battery capacity and stability within the 12–25 kg target class.
  5. Design for safe testing.Add independent E-stop power removal and an engineered overhead fall-arrest fixture.
