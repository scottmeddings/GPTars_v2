01

Design principle

AI decides what. Robot control decides how.

The LLM is the personality, reasoning and intent layer. It never directly controls motor current, PWM or unchecked joint positions. ROS 2, a behaviour supervisor and a dedicated real-time MCU translate approved high-level actions into deterministic motion.

Authority boundary: the AI may request actions such as walk, turn, gesture or stop. It cannot bypass joint limits, watchdogs, collision protection, the E-stop or actuator-power isolation.

GP-TARS selectively adapts useful parts of the TARS-AI Community V3 project rather than rebuilding everything or importing its movement stack wholesale.

GitHub deployment

Push code once. TARS can update from GitHub.

SOURCEGitHub commit
→
CIGitHub Actions
→
IMAGESGHCR
→
ROBOTWatchtower + Compose

Containers do not edit themselves or run git pull. GitHub Actions builds immutable service images tagged with both main and the commit SHA. The Ubuntu host pulls updated images from GitHub Container Registry and restarts only the services that changed.

Automatic updatesDevelopment mode can follow the latest successful `main` images.
RollbackPin the Compose stack to a previous commit-SHA image tag.
Persistent stateModels, memory, recordings, config and telemetry stay in `/opt/gptars` outside disposable containers.
Safety on updateMotion remains disabled until health checks and the MCU heartbeat are re-established.
Locomotion release rule: automatic `main` updates are for development. Once walking is enabled, motion-related services should be pinned to tested release/commit tags and promoted through a staging process.
