01

Design principle

Learn continuously. Change deliberately.

GP-TARS should become more useful through shared experience without blindly rewriting its own production software. Most improvement happens through inspectable memory, user models, learner models, behaviour policies and robot-experience data. Code changes use a separate test-and-approval pipeline.

Core rule: learning can influence how TARS responds and which bounded behaviours it prefers, but it cannot learn its way around the safety MCU, E-stop, actuator limits, privacy boundaries or release controls.

03

Layer 1

Personal memory

TARS can remember useful facts, relationships, preferences, projects and prior interactions for each person. Durable memories should include ownership, confidence, source, timestamp, privacy classification, importance and retention metadata.

Memory fieldPurpose
OwnerDetermines whose memory it is and who may access it.
ConfidenceRecords how strongly TARS believes the memory is correct.
SourceConversation, observation, explicit correction, imported document or sensor event.
TimestampSupports recency and decay calculations.
PrivacyControls whether the memory is private, household, learner or robot-wide.
ImportanceInfluences persistence and retrieval priority.
Correction behaviour: “TARS, that's wrong” is a first-class learning event. The previous memory is marked superseded/auditable rather than silently disappearing.
04

Layer 2

Adaptive teaching

TARS maintains learner-specific skill models. It records concepts attempted, confidence, recurring errors, successful teaching approaches and retention over time so a learner can continue approximately where they left off.

Skill confidenceEstimate current understanding for an individual concept.
StrengthsRecord methods and related concepts the learner already handles well.
Teaching methodsTrack whether visual examples, worked problems, hints or direct explanation work best.
Review timingUse spaced retrieval to check whether learning was retained.
  1. 01Detect learning need
  2. 02Estimate current level
  3. 03Teach using best-known method
  4. 04Ask learner to try
  5. 05Measure understanding
  6. 06Adapt and record progress
05

Layer 3

Behaviour learning

The foundation model does not need to change for TARS to become better at interacting with a person. The system can learn which communication patterns produce better outcomes.

Response lengthLearn whether a person prefers concise or deep explanations.
Technical depthAdapt detail level according to observed preference and competence.
Guided questionsMeasure whether prompting improves teaching outcomes.
InterruptionsUse interruption frequency as evidence that answers may be too long or poorly timed.
06

Layer 4

Robot experience learning

TARS learns about its own physical platform from telemetry and outcomes. Experience can tune bounded operating preferences but never safety limits.

ExperienceWhat TARS can learn
Floor type vs slipPreferred gait speed or step profile within approved ranges.
Gait vs energyWhich approved motion sequence uses less power.
Motor temperatureWhich activities create excessive thermal load.
Microphone environmentWhich noise/beam settings work best in different rooms.
Vision performanceWhich exposure, depth or tracking settings perform reliably.
NavigationCommon routes, failures and successful recovery patterns.

08

Reflection

Idle / nightly learning cycle

When idle, tars-reflection reviews recent interactions and telemetry to identify durable memories, uncertain facts, learner progress, repeated failures and improvement opportunities.

Example reflection report

Evidence rule: reflection summarises evidence; it must not manufacture lessons from sparse or ambiguous data.
09

Forgetting

Memory decay and consolidation

Long-term memory is curated using importance, confidence, recency, frequency of use and ownership. Low-value episodic details can decay or be summarised, while high-value relationships, explicit preferences and repeatedly confirmed knowledge persist.

ImportanceHow consequential the memory is.
ConfidenceHow well supported it is.
RecencyWhether it is still likely to be current.
FrequencyHow often the memory is useful or confirmed.

Users should be able to inspect, correct and delete their personal memories.

12

Non-negotiable boundaries

Safety, privacy and governance

  • Learning services cannot bypass the safety MCU or physical E-stop
  • Actuator limits remain deterministic and outside the LLM
  • Learned motion parameters stay inside approved envelopes
  • Sensitive personal information remains identity-scoped
  • Production self-modification is prohibited outside the governed release pipeline
  • Model or code changes must be testable and reversible
